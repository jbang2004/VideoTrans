# VideoTrans 项目重构方案

## 项目现状分析

### 当前架构
```
前端 → FastAPI → Ray Serve编排器 → 各种处理服务
     ↓
   Supabase数据库
```

### 存在的问题
1. **紧耦合**：前端直接调用后端API
2. **单点故障**：FastAPI成为瓶颈
3. **状态管理**：缺乏统一的状态机制
4. **扩展性**：难以支持多实例部署
5. **监控性**：缺乏完整的任务生命周期追踪

## 重构目标架构

### 目标架构图
```
前端 ←→ Supabase数据库 ←→ 实时监听器 → Ray Serve编排器
     ↑                    ↓              ↓
   实时UI更新          事件驱动处理      分布式任务处理
```

### 2. 核心组件重构

```
职责：

关键特性：

- 自动故障恢复
```

#### 2.3 事件处理器 (EventProcessor)
```
职责：
- 处理具体的业务事件

- 更新任务状态和进度

- TranslationProcessor: 处理翻译相关事件
```

### 3. 前端交互重构

#### 3.1 任务提交流程
```javascript
// 新的任务提交方式
class TaskManager {
    async submitVideoTask(videoId) {
        // 1. 创建任务记录
        const { data: task } = await supabase
            .from('tasks')
            .insert({
                video_id: videoId,
                status: 'pending'
            })
            .select()
            .single()
        
        // 2. 触发下载和预处理
        await supabase
            .from('tasks')
            .update({ status: 'start_preprocessing' })
            .eq('task_id', task.task_id)
        
        return task
    }
    
    async startTTS(taskId) {
        await supabase
            .from('tasks')
            .update({ status: 'start_tts' })
            .eq('task_id', taskId)
    }
    
    async cancelTask(taskId) {
        await supabase
            .from('tasks')
            .update({ status: 'cancelled' })
            .eq('task_id', taskId)
    }
}
```

#### 3.2 实时状态监听
```javascript
class RealtimeTaskMonitor {
    constructor() {
        this.setupRealtimeSubscription()
    }
    
    setupRealtimeSubscription() {
        supabase
            .channel('task_updates')
            .on('postgres_changes', {
                event: '*',
                schema: 'public',
                table: 'tasks'
            }, (payload) => {
                this.handleTaskUpdate(payload)
            })
            .subscribe()
    }
    
    handleTaskUpdate(payload) {
        const { eventType, new: newRecord, old: oldRecord } = payload
        
        switch (eventType) {
            case 'UPDATE':
                this.updateTaskUI(newRecord, oldRecord)
                break
            case 'INSERT':
                this.addTaskToUI(newRecord)
                break
        }
    }
    
    updateTaskUI(newTask, oldTask) {
        // 状态变化
        if (newTask.status !== oldTask.status) {
            this.updateTaskStatus(newTask.task_id, newTask.status)
        }
        
        // 进度变化
        if (newTask.overall_progress !== oldTask.overall_progress) {
            this.updateProgress(newTask.task_id, newTask.overall_progress)
        }
        
        // 阶段详情变化
        if (JSON.stringify(newTask.stage_details) !== JSON.stringify(oldTask.stage_details)) {
            this.updateStageDetails(newTask.task_id, newTask.stage_details)
        }
        
        // 完成通知
        if (newTask.status === 'completed' && newTask.hls_playlist_url) {
            this.notifyTaskCompleted(newTask.task_id, newTask.hls_playlist_url)
        }
        
        // 错误处理
        if (newTask.status === 'error') {
            this.showError(newTask.task_id, newTask.error_message)
        }
    }
}
```

### 9. 总结

这个重构方案将VideoTrans从传统的请求-响应架构转变为现代的事件驱动架构，具有以下核心优势：

1. **完全解耦**: 前后端通过数据库状态通信
2. **真正实时**: 毫秒级状态同步
3. **高可扩展**: 支持水平扩展和负载均衡
4. **强鲁棒性**: 自动故障恢复和补偿机制
5. **易维护**: 清晰的模块划分和状态管理
